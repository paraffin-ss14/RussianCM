# Переводная — редактор локализации

Локальный веб-интерфейс для сравнения `en-US` и `ru-RU` и редактирования записей Fluent. Работает с файлами проекта напрямую, не требует сборки игры, аккаунта или внешнего сервиса перевода.

## Запуск на Windows

Требуется Python 3.10 или новее. Из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File Tools/localization/start.ps1
```

При первом запуске скрипт создаст отдельное окружение `.venv` и установит `fluent.syntax` (нужен интернет). Затем откроется браузер. Следующие запуски работают без интернета. Для остановки сервера нажмите `Ctrl+C` в его терминале.

Запуск вручную, в том числе на Linux/macOS:

```sh
python -m pip install -r Tools/localization/requirements.txt
python Tools/localization/server.py --open
```

Порт выбирается автоматически. Для постоянного адреса добавьте `--port 8765`. Для другого проекта или языков: `--root /path/to/project --source en-US --target ru-RU`. Сервер принимает подключения только через `127.0.0.1`.

## Работа с переводами

1. Выберите раздел и фильтр. По умолчанию показаны записи, совпадающие с оригиналом: сюда попадают скопированные английские тексты.
2. Ищите по ключу, тексту оригинала/перевода или пути файла.
3. Выберите запись. Слева — оригинал, справа — редактируемая запись вместе с её атрибутами. Комментарий оригинала отображается отдельно.
4. Переводите текст после `=`, сохраняя ключ, переменные, ссылки, функции и разметку. Кнопка «Взять за основу» копирует исходную запись в редактор.
5. Нажмите «Сохранить» (`Ctrl+Enter`) или «Сохранить и дальше» (`Ctrl+Shift+Enter`). Только сохранение меняет файл. `Tab` в редакторе вставляет четыре пробела, `/` вне поля ввода открывает поиск.
6. Просмотрите изменения через Git. Для отмены уже сохранённого перевода используйте обычный просмотр и откат нужного фрагмента в Git; «Отменить правку» отменяет только несохранённый текст.

## Что означают статусы

В списке «Тип записей» можно выбрать **Сущности (entity)**. Редактор читает
`Resources/Prototypes` и `Content.CMU/Resources/Prototypes`, включая варианты
`CreateVariants`. Для каждого прототипа он сопоставляет `ent-ID` (либо
`localizationId`), `name`, `description` → `.desc` и `suffix` → `.suffix`.
Исходные FTL имеют приоритет над YAML; недостающие поля берутся из YAML и родителей
в порядке обхода движка (сначала непосредственные родители).

В карточке показаны ID, путь YAML, родители и признак абстрактного прототипа.
По ним также работает поиск. Даже если записи нет в английском FTL, она доступна
для перевода. Сохранение создаёт запись в `ru-RU/Entities/<путь прототипа>.ftl`
или обновляет уже существующий русский ключ в его текущем файле. YAML не меняется.
Изменение исходного прототипа или использованного родителя требует перечитать индекс.

Для сущностей статус «Отсутствуют» означает отсутствие **явного** перевода ключа
или его исходных полей: в игре некоторые поля могут уже наследоваться от русского
родителя. Редактор не запускает движок; динамические суффиксы категорий и изменения
метаданных компонентами во время игры не вычисляются. Некорректные прототипы
пропускаются с предупреждением, остальные остаются доступны.

| Статус | Значение |
| --- | --- |
| Совпадают с оригиналом | Значения и атрибуты одинаковы. Это кандидаты на перевод, а не достоверная оценка его отсутствия: имена, числа и ссылки могут совпадать. |
| Отсутствуют | Нет ключа, основного значения или одного из исходных атрибутов. |
| Отличаются | Запись полна и отличается от исходной. Это не проверка качества или языка текста. |
| Только в переводе | Ключ есть в целевой локали, но отсутствует в исходной. Он тоже доступен для редактирования. |

Ключи сопоставляются по всей локали. Если русский перевод находится в другом файле, редактор изменяет именно этот файл. Отсутствующая запись создаётся по относительному пути оригинала. Русские атрибуты, которых нет в оригинале, сохраняются.

## Проверки и ограничения

- Проверка синтаксиса Fluent, имени ключа, обязательных значений/атрибутов и набора переменных перед записью.
- Поддержка принятых в Robust компактных комментариев и переменных в именованных аргументах Fluent.
- Изменяется только выбранная запись; комментарии, соседние записи, BOM и стиль переноса строк файла сохраняются.
- Запись через временный файл и атомарную замену. Если исходный или целевой файл изменился после открытия записи, сохранение отклоняется, а введённый текст остаётся в редакторе. Скопируйте свою правку перед повторным открытием записи.
- «Перечитать файлы» обновляет полный индекс после внешних правок. Первое чтение большого проекта может занять несколько десятков секунд.
- При ошибках синтаксиса и дубликатах ключей индекс показывает диагностику и блокирует сохранение. Ошибки исправляются в обычном текстовом редакторе.
- Не проверяет корректность игрового форматирования, существование всех ссылок, смысл перевода или все случаи выполнения функций Fluent. После содержательных переводов нужна проверка в игре.
- Автоматического перевода, публикации и массовой перезаписи файлов нет.

## Проверка инструмента

```sh
python -m unittest discover -s Tools/localization -p "test_*.py" -v
```

Тесты работают с временным проектом и не меняют локализацию игры.
